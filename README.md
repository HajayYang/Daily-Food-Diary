# 一日食记 · Daily Bites

一个轻量、开源、支持中英日韩四种语言的饮食记录网页。好好吃饭，慢慢记录。

## 功能

- 按日期记录早餐、午餐、晚餐和加餐，支持编辑与删除。
- 填写食物、份量、可选的估算热量及备注。
- 查看每日记录数、不同食物名称数与已填写的热量总和。
- 浏览器 localStorage 保存，刷新后保留；JSON 导出与预览合并导入，支持可选的 Supabase 账号同步。
- 常吃食物与餐单收藏、食品条码查询、每周饮食运动报告、按禁忌筛选的购物清单。
- 今天吃什么：按菜系、菜名、别名或食材搜索 108 道菜，查看用量与做法，支持人数调整和离线使用。
- 可调份量的常吃套餐、菜谱营养估算与确认入账、食材库存和临期推荐、体重/腰围/臀围趋势、饮水与运动补水参考。
- 支持安装到桌面的 PWA、完整应用离线使用、可关闭的页面内提醒、定期备份提醒，以及隐私与数据中心。
- 适配电脑与手机，原生 HTML、CSS、JavaScript，菜品查询使用随站点提供的 SQLite / WebAssembly 引擎，无需外部 CDN 或前端打包。

## v1.1 日常健康工具

顶部导航可跳转到“用餐计划与库存”“安装与数据管理”和“今天吃什么”。所有新工具支持简体中文、英语、日语、韩语和四种主题，默认保存于本浏览器。

- **常吃套餐**：为当前餐次命名并收藏，使用时选择日期与餐次，每种食物可独立调整 0.1–10 倍份量。热量及已知营养值同比换算，零值保留，未知值不变成零。
- **菜谱到饮食记录**：菜谱详情可以核对食材克数、实际用油、本锅总份数与计划食用份数，安排到某日某餐。计划本身不计入摄入；吃完后确认实际份量再入账。同一计划不会重复入账，入账与计划状态使用同一持久化回滚事务。移除计划保留已有饮食记录，库存不自动扣减。
- **家庭食材库存**：记录剩余数量、单位和可选保质期，修改数量可登记消耗。按实际当天判断临期（含未来 3 天）和过期，库存查菜跨全部 108 道菜；临期优先，过期和零数量排除，按已设置的已知过敏原与关键词筛选。名称匹配不代表数量充足或保证无过敏原，仍需检查实际食材。仅近似名称不同的食材可能无法匹配。
- **食谱营养估算**：通用原料采用 USDA SR Legacy 近似值，明确区分生食材和熟米饭；鸡蛋 50 g/个、蒜 3 g/瓣仅作可修改初始值。未建立可靠映射的食材保持未知，可输入实际克数与可靠标签的每 100 g 热量、蛋白质、碳水和脂肪。界面展示已知部分与缺失数；任何食材缺失的营养项目，保存整道菜时仍为未知。不是实验室检测，不计算烹调营养损失，也不会将生抽 ml 自动当作 g。
- **身体趋势**：每天一组体重及可选腰围、臀围，可切换 28 天趋势图并查看、编辑或移除明细。每个相邻周至少 2 天体重才比较周均值，建议同时显示近 14 天已确认且无热量缺失的完整日摄入。不会用单日波动自动调整能量目标，也不改写已保存的运动估算体重。
- **饮水**：快速添加 250 / 500 ml 或自定数量，支持撤销、个人饮水参考和温和/炎热环境设置。参考一般健康成人温和环境约 1500–1700 ml/天；已完成运动期间可参考约 400–800 ml/小时并按实际出汗调整。运动参考不会自动叠加到目标，饮水不与食品含水量相加为“总需水量”。
- **离线安装与提醒**：HTTPS 或 localhost 首次联网缓存完整公开资源后，可安装并离线重开应用、查询菜品库、记餐和管理本地数据；外部食品查询、识图、云同步仍需联网。提醒默认关闭，只有主动点击才申请系统通知权限；按浏览器本地时区在应用打开时检查饮食/运动提醒。静态网站无法保证应用关闭后定时通知，不提供后台闹钟。备份可选 7 / 14 / 30 天提醒，导出发起时间不代表浏览器已完成保存。
- **隐私中心**：查看本地存储用量、云会话状态、数据存放位置及最近发起导出的时间，导出完整备份或打开同步设置。输入 `DELETE` 后才删除本应用的本地记录、设置、背景图、服务工作线程和缓存；保留同域其他应用的数据。重新打开会准备新的公开缓存；不删除云端备份或下载文件。

完整备份升级为 **version 4**，包含 `wellbeing` 的库存、计划、测量、饮水与偏好，支持导入 1–4 版并预览合并冲突。旧版本应用不支持 v4 备份，请使用新版恢复。备份不包含背景图片、系统通知权限、云会话或服务密钥；上传 Supabase 前的缺项检查也包含新集合。

PWA 的 `manifest.webmanifest`、模块 Service Worker 和图标均使用相对 URL，适配 GitHub Pages 项目子路径。离线缓存仅允许 `offline-assets.js` 中明确列出的公开文件，不缓存 API、图片识别请求或健康记录。修改公开资源后应同时更新 `service-worker.js` 的缓存版本；新资源全部下载成功后才可切换，页面显示更新按钮，避免使用中自动刷新。

选择菜系后，可按菜名、别名或食材搜索，并叠加蔬菜豆蛋、肉鱼、米面类型筛选；选择“全部菜系”可跨 108 道菜查询，结果每页最多 12 道。切换菜系保留搜索词和类型筛选，“重置菜谱搜索”回到家常菜并清空条件。搜索后直接显示首道匹配菜的食材、用量、预计时间、分步做法、配餐与过敏原提示；无匹配结果时不展示旧做法。

可选 1 / 2 / 4 人份，食材用量等比例调整，烹饪时间不按人数线性缩放。原料通常按生重可食部分计，炒饭使用熟米饭、面条使用干重；泡发、腌制及商用预处理食品须同时查看步骤和包装说明。地域菜谱为原创家庭简化版，保留主要风味，同名菜在不同地区可有不同做法；不是唯一的传统标准。特殊食材明确购买状态，如已泡发海参、正规熟制大肠、正规冷藏预腌鳜鱼和毛豆腐。

用量为家庭烹饪参考，须结合实际调味品标签、份量、锅具与成熟度调整。菜谱不会自动记录为已吃，也不提供未经核实的营养数值。菜谱库覆盖有限，未收录时给出换词提示。

菜品已存入真正的 SQLite 数据库 `data/cookbook.sqlite`，包含 108 道菜、9 个分类、128 种食材及用量、步骤、过敏原与四语言翻译。界面通过 Worker 中的 SQLite 引擎完成筛选、搜索和分页，不再导入种子菜谱数组。随站点提供引擎，无需外部 API、CDN 或密钥，GitHub Pages 可直接使用。校验后的数据库可缓存，页面打开后断网仍可查询；加载失败时显示重试入口，其他记餐功能可独立使用。

数据库结构、SQL 查询、维护、缓存边界与可选 Node 只读 API 见 [菜品数据库说明](database/README.md)。`recipes.js`、`regional-recipes.js` 和 `locales.js` 保留为可重复导入的种子；修改后运行 `npm run db:build` 并一并提交数据库与校验清单，再运行 `npm run db:check`、`npm test` 和 `npm run test:browser`。营养数据带具体单位与来源，缺失保持未知，不套用不同生熟状态的数据。

## 拍照记餐

点击日期栏旁的“拍照记餐”，可调用手机相机或上传 JPG/PNG/WebP 餐食图。确认发送后识别多种食物，修改名称、份量、热量、蛋白质/碳水/脂肪，勾选后一次保存；低把握项目默认不勾选。未确认、取消、无餐食或识别失败不会写入记录。

此功能支持 **OpenAI、阿里云百炼 Qwen 或 DeepSeek + Cloudflare Worker**，需要单独部署识别服务并配置模型密钥与访问码。详见 [部署与本地开发说明](worker/README.md)。GitHub Pages 只能提供网页，不能运行 Worker；仓库中没有模型密钥，也不会把密钥写进网页。网页中的访问码只在本次页面内存中保留，服务地址可保存在浏览器。管理员可在 `photo-service` meta 标签预设服务地址。

照片发送前在本地压缩和重新编码，不保存至食记或导出文件；仅发送照片和界面语言，不发送身体数据及既有记录。使用时需明确同意将照片交给配置服务及其选定的视觉模型提供方（OpenAI、阿里云百炼或 DeepSeek）按其政策处理。识别是估算，不能从照片精确测量重量和烹调油；模型自评不是准确率。修改份量后要同步核对营养值，当前不会自动按重量缩放。手动记餐不受服务可用性影响。

## 运动计划与语言

- 运动计划支持健身 / 力量、游泳、跑步、羽毛球、乒乓球、网球、徒步、其他有氧 / 骑行及拉伸恢复。快捷按钮可生成对应项目的动作或活动内容，预览调整后保存；也可按星期自动安排。
- 每个项目使用对应强度的近似 MET，结合保存的体重及时长估算消耗。新增有氧项目仅在完成且达到所选中高强度时计入周有氧等效分钟；旧版力量、有氧、骑行记录无需迁移。
- 右上角语言选择支持简体中文、English、日本語、한국어。菜单、表单、图表、静态食材科普、运动示例与提示均本地翻译，无需翻译 API。日期按所选语言显示；语言偏好仅保存在当前浏览器。
- 手写食物名、份量、备注、已保存的运动内容，以及在线食品库的原始名称、品牌和配料保持原文。生成新运动示例时使用当前语言，不修改历史记录。常见食材支持当前语言与中文搜索；外部食品库覆盖范围依其原始数据而定。
- 食物搜索采用统一外框：聚焦时整个控件高亮，输入后保留边框提示，联网加载时整框显示动态光效。尊重系统“减少动态效果”设置，键盘聚焦仍然可见。

翻译文案维护在 `locales.js`，`i18n.js` 管理偏好、参数化消息、日期和界面更新；用户内容用 `translate="no"` 排除。新增界面文案时请补齐三种翻译，并运行覆盖检查。

## 个性化外观

点击页面右上角“外观设置”，即时预览并自动保存：

- 云朵白、深夜黑、森林绿、晴空蓝四种主题，覆盖卡片、表单、图表文字和弹窗。
- 普通按钮或液态玻璃按钮（半透明、背景模糊和高光；不支持模糊的浏览器仍能正常操作）。
- 选择本地 JPG、PNG、WebP 图片作为背景，原图最大 12 MB、8000 万像素，处理后最长边不超过 2400 像素。
- 图片透明度 0%–100%：0% 完全显示，100% 完全透明；卡片和文字不受影响。可单独移除图片，或恢复默认配色与按钮。

主题、按钮及透明度使用 localStorage；背景图片使用 IndexedDB，均只保存在当前浏览器。不会上传服务器，不影响饮食或训练数据；外观与背景不包含在饮食 JSON 导出中。清除网站数据会清除这些设置。浏览器禁用本地存储或空间不足时会显示提示，图片保存失败不替换原背景。

## 主页与食物百科

健身计划位于每日概览后，桌面主栏约占 62% 宽度，手机端优先显示。保留训练生成、动作组次、消耗估算、完成打卡及饮食记录功能。

“认识食物”提供苹果、橙子、猕猴桃、香蕉、西兰花、燕麦、鸡蛋和原味酸奶 8 张食物卡片，可按类别筛选或搜索。展示每 100 克可食部分的近似热量、营养特点、单次份量及搭配建议。苹果不标为高维 C 食物；份量只是一般健康成人的搭配参考，需结合全天总量与个人需求。数据参考 USDA 与中国居民膳食指南（2022），来源可在页面展开查看。

液态玻璃按钮增加折射边缘、弧面高光、投影和悬停光泽，四种主题均可使用；尊重系统“减少动态效果”设置。

## 在线食品查询 API

“认识食物”提供两种来源：精选食材保留本地科普、份量与搭配建议；在线食品库接入 [Open Food Facts](https://world.openfoodfacts.org/)，点击“在线食品库”输入名称后查询，支持回车、分页、失败重试及返回本地浏览。无需 API 密钥，无需后端，适合 GitHub Pages 等静态部署。

实时查询改用官方 Search-a-licious，经应用同源 `/api/food-search` 或独立 Worker 转发；每页 8 项。常见中文食材名映射为英文查询。正式食品库主要收录包装食品，覆盖和数据质量因地区及语言而异，不能等同完整生鲜百科。数据缺失保持未知，优先核对包装标签。

**GitHub Pages 不能运行查询服务。** 默认页面在实时接口故障时读取随站点发布的 `food-cache.json`，展示带独立抓取时间的有限备用结果，明确标为“快照 / 非实时”。面包、牛奶等有备用数据，未收录的查询不会冒充无匹配结果。无需账号即可使用快照；完整实时检索需部署食品查询 Worker 并填写 `food-service` meta 地址。具体步骤、限制与手动刷新见 [food-worker/README.md](food-worker/README.md)。

Node 部署运行 `npm start` 即包含查询 API。相同查询缓存 10 分钟，响应保留品牌、标签营养、配料、过敏原及来源链接；服务端只访问固定官方地址，不转发登录 Cookie、模型密钥或健康记录。服务故障、超时、限流与连接失败分别提示。静态备用数据来自正式库，不使用 `.net` 测试库或第三方公共代理。

查询词会发送到配置的食品服务及 Open Food Facts，饮食、身体资料和背景不随查询发送。数据由 Open Food Facts 贡献者维护，按 [ODbL](https://opendatacommons.org/licenses/odbl/1-0/) 标注；快照授权见 [food-cache.LICENSE.md](food-cache.LICENSE.md)。

## 热量可视化

- 环形饼图：所选日期早餐、午餐、晚餐和加餐的已填写热量占比。
- 条形图：同一尺度对比当天四餐热量。
- 堆叠柱状图：截至所选日期的最近 7 天，各餐以固定颜色区分。支持点击或键盘选择日期，附可展开的数据表。
- 直方图：当天单条食物记录在 0–199、200–399、400–599、600–799、≥800 kcal 区间的条数。不是每天总量的分布，最后一组为开放区间。
- 添加、编辑、删除记录与切换日期会同步刷新图表。明确区分“未记录”“未填热量”和填写了 0 kcal；缺失项不计入总和与比例，无正数热量时不绘制饼图扇区。
- 原生 SVG/CSS 绘图，无 CDN 或图表库依赖。kcal 即千卡，日常也称大卡；热量和卡路里在这里是同一项能量指标。

## 健身与健康配餐

- 可手动填写卡路里及蛋白质、碳水、脂肪；6 种通用食材支持按可食重量估算。生熟状态见选项，品牌、油脂与做法会影响数值。
- 设置健康维持、增肌或体重管理目标，可选体重和个人每日能量参考；不自动生成减脂缺口、不抵扣运动消耗。
- 每天可添加多次力量、有氧或拉伸训练，编辑时长与强度，标记完成或删除。所选日期所在周按周一至周日统计：仅已完成有氧按中等强度等效分钟计，高强度乘 2；力量按不同日期计数。
- 展示营养素合计、缺失数据、规律训练者蛋白质参考、灵活的每餐热量分配、训练前后用餐建议。
- 应用内提供 WHO 健康饮食/身体活动、哈佛健康餐盘、ISSN 蛋白质声明及 USDA 食物数据参考链接。

这些是面向一般健康成年人的记录与教育参考，不能保证个体饮食达标。未成年人、孕哺期人群和有特殊健康需求者应由专业人员制定计划。1200–6000 kcal 仅为输入校验范围，不是推荐范围；不确定个人需求时可不填能量目标。

## 每日训练内容与身体数据估算

在“设置我的目标”中填写体重、身高、年龄、代谢公式性别和日常活动水平；可选择训练经验。各项可留空，资料不足时不输出假定值。

- 点击“生成当天训练内容”预览按星期、目标、经验安排的力量 / 快走 / 恢复示例，含动作、组次、休息及热身放松。可调整后保存，不会覆盖已有训练，也不会自动标为完成。
- 手动安排支持器械、自重、步行、跑步、骑行、一般有氧和拉伸，填写训练内容及用于该次估算的体重。保存体重后，后续修改个人体重不会改写该次估算；旧训练无体重时使用当前个人体重并明确标注。
- MET 总消耗 = MET × 3.5 × kg ÷ 200 × 分钟；额外消耗将 MET 换为 MET−1。MET 为运动类别与强度的近似参考，并不代表实际测量。训练时长包含休息时尤其可能有误差。
- 计划消耗包含当天所有训练（含已完成），已完成消耗只统计打卡完成的训练；缺少体重的训练单独提示，不当作零消耗。
- Mifflin–St Jeor 静息代谢 = 10×kg + 6.25×cm − 5×年龄 + 性别常数（男 +5 / 女 −161）；维持能量 = 静息代谢 × 1.2/1.375/1.55/1.725。活动系数已含平常训练，不再次加运动消耗，也不自动覆盖手填能量目标。
- 根据数据完整度、目标、训练强度及恢复需要给出建议。估计适用一般健康成年人，不代替专业营养或运动处方。手填目标低于估算静息代谢时提示核对，不把代谢值当作个人安全阈值。

身体数据、训练内容和估算体重均保存在当前浏览器，随 JSON 一起导出。参考：[Adult Compendium](https://pacompendium.com/)；[Mifflin–St Jeor](https://pubmed.ncbi.nlm.nih.gov/2305711/)。

## 六类营养信息与次日饮食建议

每条食物记录、精选食材、在线商品都可展开六类营养信息：糖类（碳水化合物，单列其中糖）、脂肪、蛋白质、维生素、无机盐（矿物质）和水。维生素目前收录 C、A（RAE）、D、B12，矿物质收录钙、铁、钾、钠；不是全成分分析，不将不同单位或不同微量营养素相加。另支持记录膳食纤维和饱和脂肪。编辑时展开“补充糖、水、维生素与无机盐”，填写**本条实际份量**的数值及来源。空白代表未知，明确的 0 会保留。旧记录无需迁移。

内置通用食材沿用 USDA FoodData Central / SR Legacy 近似成分，生熟状态见食物卡片；按克数换算时，所有已知项目一起填入，微量数值保留至三位小数。请优先使用实际产品标签，不能把通用值当作检测结果。在线 Open Food Facts 缺失项标“未提供”；API 微量营养素标准值的 g 转换为页面 mg / µg，不能直接拿标签显示单位解释 API 数值。API 的维生素 A 数据未保证 RAE 定义，因此不自动转换成 RAE。照片不能可靠推断维生素、矿物质和水，保留未知，可保存后按可靠资料编辑。

“把今天的记录，变成明天的搭配”使用所选日期的饮食和**下一天**的运动生成三餐及可选加餐，支持均衡饮食、蛋奶素、纯素，不需要新 API 或密钥。建议不会自动存为已吃记录。只有勾选已完整记录全天饮食，并且相应营养项目没有缺失，才比较能量、运动蛋白质、宏量供能比例、纤维和钠；可选确认当天是否包含五类食物，不从菜名猜测。修改食品、份量或营养数值后，需重新确认完整性和食物类别。

手填能量目标只用于可调整的餐次分配示例，**不是示例菜单的营养计算值**；不根据昨天的差额要求补吃、跳餐，不将运动消耗直接加回摄入。低于估算静息代谢的目标会暂停用于分配。一般成人宏量比例参考碳水 45%–65%、脂肪 20%–35%（DRI），纤维参考至少 25 g/天、钠参考少于 2000 mg/天、饱和脂肪供能参考低于 10%（WHO）。总糖不等于游离糖；食物水分不是额外饮水目标。维生素和矿物质展示已填合计及缺失条数，不用单日记录诊断缺乏或推荐补剂剂量。依据可在页面的“建议依据与适用范围”查看。

饮食偏好与每日确认保存在 `daily-bites.next-day.v1`，随 JSON 导出；保存失败会回退控件并保留原数据。原有存储不可读时不覆盖原记录。建议面向一般健康成年人，特殊情况应按个人医嘱调整。

## 收藏、条码与生活工具

- **常吃食物与餐单**：每条食物旁点击“收藏”，或在生活工具中保存所选日期的某一餐。使用收藏时预览食品并选择日期、餐次，确认后创建新 ID 的记录，保留原份量及营养值，不修改历史记录。最多 100 个收藏、每个最多 50 项；复用前核对当前禁忌和实际份量。
- **食品条码**：点击“条码记录”，手填 EAN-8 / UPC-A / EAN-13 / GTIN-14 数字，校验正确后请求 Open Food Facts `/api/v2/product/{code}.json`。支持原生 `BarcodeDetector` 和摄像头的浏览器可在本机扫描；需要 HTTPS 或 localhost 及摄像头权限。不支持时仍可手填，不上传摄像头画面。包装数据不保证完整或无过敏原。核对每 100 g / 100 ml 标签基准，按实际份量缩放已知营养值，未知值不变成零；填写到编辑表单后再次保存，不自动计入饮食。每次查询间隔至少 1 秒，当前会话缓存最多 50 项。
- **饮食禁忌**：可勾选乳、蛋、大豆、含麸质谷物、花生、树坚果、鱼、甲壳类与贝类、芝麻；另支持最多 20 个食材关键词。次日菜单从带已知过敏原标签的内置食材中选取，并匹配中英日韩常见别名；菜单展示具体食材，午晚餐尽量包含两种蔬菜。没有可用选项时提示手动调整。并非专业过敏筛查，仍需检查品牌配料、强化营养及交叉接触；手填、收藏和外部商品不自动认定安全。
- **购物清单**：点击次日菜单下的按钮，按当前饮食偏好和禁忌生成具体食材，同一天同名项目去重，保留已勾选状态。可手动添加、删除或移除已购项目；最多 200 项。数量按人数、实际食量和家中库存调整，不从示例热量推算采购重量。
- **周报**：展示所选周的周一至周日，有记录天数、确认完整天数、不同食物名称数、每日已记录热量条形图、蛋白质/纤维/钠/饱和脂肪已填合计与缺失条数、已完成有氧等效分钟及力量天数。每日平均热量仅采用已确认完整且热量无缺失的日期；空白日不计为零摄入，名称数不作为食材多样性评分。修改记录后会同步更新。

## JSON 恢复与可选账号同步

右上角“备份与同步”选择 JSON 文件（最大 2 MiB），兼容 version 1 / 2 / 3 / 4 导出。所有数据先校验，再预览新增、重复、冲突数量。默认合并新增、保留本地冲突内容；可切换采用备份内容，并可明确选择是否采用备份身体目标、禁忌和饮食偏好。按 ID 识别冲突，不按食品名去重，不删除本地未出现在备份中的记录。导入原始营养数据，建议偏好与完整性确认按实际数据重新判断。

导入使用持久化回滚日志：创建恢复副本失败时不开始写入；中途保存失败时恢复导入前所有数据，未完成的恢复会在刷新时重试。需要额外浏览器空间，原始副本保留在 `daily-bites.import-journal.v1` 直到恢复完成。另一标签页修改数据时当前页暂停编辑，刷新后再继续，避免旧状态覆盖新数据。备份包含个人健康信息，请妥善保存。

**无需云账号也可使用全部本地功能。** 可选跨设备同步使用自己的 Supabase 项目，含邮箱注册、验证后登录、退出、手动上传、下载预览及合并恢复。提供数据库表、账号行隔离策略和带版本检查的写入函数；配置与步骤见 [sync/README.md](sync/README.md)。上传需要逐次确认，下载不会直接覆盖本地数据；另一设备更新云端后拒绝旧版本上传。此仓库不附带公共云数据库、密钥或已经启用的线上同步服务。

## 本地运行

需要 Node.js 22.13 或更高版本（SQLite 支持），建议 Node.js 24。数据库及浏览器引擎已包含在仓库。

```sh
npm start
```

在本地电脑运行时，访问 `http://localhost:3000`。无需安装应用依赖。此服务器仅公开网页资源白名单，不提供 Worker 目录及本地密钥文件。手动饮食数据保存在浏览器；拍照识别另行请求已配置的服务。部署时将仓库根目录的 `index.html`、两个 CSS 文件及全部浏览器 JavaScript 模块（排除 `server.js`）放到静态网站托管平台；不要公开 `worker/`、本地密钥、开发工具、测试目录或同步部署脚本。正式部署使用 HTTPS；同时发布 `food-cache.json`、`data/` 和 `vendor/sqljs/`；Supabase 数据库、拍照 Worker 和可选实时食品查询 Worker 需单独配置。

## 数据与隐私

默认将饮食与健康资料保存在当前浏览器、当前站点下，无需账号；只有主动配置和确认上传云同步时，备份才会发送到你指定的 Supabase 项目。云同步密码不保存，登录令牌仅在本标签页 sessionStorage 中保留，退出后清除；服务地址及公开客户端 key 可保存在 localStorage，均不包含在备份中。选择拍照识别时，经同意的照片会发送到单独配置的识别服务及其选定的视觉模型提供方（OpenAI、阿里云百炼或 DeepSeek）。清除网站数据、更换浏览器或网站地址会导致原记录不可见，请定期导出备份。支持导出与预览合并导入；外观背景及照片不随备份迁移。共享设备上的其他使用者可能看到记录。

热量由使用者填写；空值不计入总和，显示总量可能不完整，仅供记录参考。食物种类按完整名称去重，不自动识别菜品中的食材。
