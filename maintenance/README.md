# Codespaces read-only inspection

The `Maintain Codespaces safely` Actions workflow runs only when manually dispatched. It needs the repository Actions secret `GH_CODESPACES_TOKEN`, restricted to this repository, with `Codespaces` and `Codespaces lifecycle admin` read/write permission. It uses GitHub's own runner so its credential is not replaced by the managed cloud environment's repository-authentication gateway.

The default inventory operation only calls GET endpoints. The optional probe operation accepts a SHA-256 fingerprint from a verified inventory, starts only a previously stopped space, privately reads its Git/file inventory through SSH, and stops it again in a finally block. The recovery-export operation uses GitHub’s official no-start export to save the currently checked-out branch to a repository branch. It does not preserve other local branches or ignored files. The separate delete operation is disabled unless the user explicitly confirms current-branch-only preservation. It verifies the repository, owner, target fingerprint, stopped state, unchanged last-used time, latest successful export and actual backup branch commit before deleting one specific space. It verifies completion through a missing-space response and never deletes backup branches. Active or mismatched spaces are left untouched. A successful inventory is not proof that code, ignored files or private configuration have been backed up. Those checks remain required before any deletion.

Codespace names, branch status and last-used dates are encrypted before artifact upload, because this is a public repository. The committed PEM file is only a public encryption key. The private key is retained outside the checkout in the owner's Codex workspace, not in Git or Actions. The inspection report uses a fresh AES-256-GCM key, wrapped with RSA-OAEP-SHA256, and artifacts expire after three days.

This encryption key is for maintenance reports, not a Windows publisher certificate. Do not commit the private key or a personal access token. Before replacing the public key, retain the private key needed to read previous reports. If the private key has been lost, perform a new inspection with a new key; do not delete Codespaces based on an unreadable report.
